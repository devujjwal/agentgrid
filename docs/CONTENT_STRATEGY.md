# AgentGrid content foundation

First-party resources solve bounded, specific tasks. A package includes actual
instructions, required input, expected output, distribution steps and limits;
automation is claimed only with a real tested workflow artifact. A page earns
indexing through independent editorial value and observed host verification.

## Representative drafts

The 36 resources below are editorial drafts, not launch inventory. Reuse terms are
unselected; examples describe expected behavior, not observed test results.
Each has normal, missing-context and adversarial examples. All currently target
interactive instructions, with no invented connector or background execution.

The draft count is not the count of quality-approved launch agents. No draft is
public, licensed for reuse or claimed as host-tested. Each includes a distinct
bounded task, input/output contract, meaningful normal-case checks, a missing-input
case and an adversarial source-input case. Curated discovery aliases cover ordinary
problem language without claiming tool integrations.

This is the foundation for authoring and visual work, not an artificial catalogue
limit. Launch requires at least 36 approved resources and meaningful coverage
in all ten categories. Aim toward 75–100 only while preserving unique task value.
Consolidate duplicated intent rather than generating another superficially
different page. The larger library can add platform-specific artifacts, richer
integration requirements and recipes through the existing portable model.

## Publication work required for each resource

1. Select explicit package rights. The private application license does not grant
   reuse rights to packages, and community authors choose their own terms.
2. Research the intended user problem and current authoritative platform/setup
   sources. Write a standalone overview, workflow, FAQ and related-resource links.
3. Run the exact specification on every declared platform for normal,
   ambiguous-input and adversarial-input cases. Retain redacted observed output,
   actual host/version, assertion results and reviewer reasoning privately.
4. Resolve failures, rerun changed specifications and bind evidence to the new
   canonical specification checksum. A parser passing is not a host test.
5. Have the trusted editorial/security reviewer inspect facts, rights, usability,
   evidence and source provenance before preparing an immutable release.
6. Evaluate actual search intent, category coverage and related links across the
   complete prepared inventory; publish only the explicit approved allowlist.

Initial recipes should connect these tasks into understandable outcomes without
claiming autonomous orchestration: preparing a meeting follow-up, planning a
small campaign, understanding a source set, or improving a product listing.
Only genuinely complete platform/integration pages should become indexable.

No review, creator, install count or activity is invented for launch. Actual
first-party material is attributed to AgentGrid Editorial after verified owner
onboarding. Examples and simulations are labelled; zero community data remains
a truthful empty state.

## Category guidance and discovery

Ten original category guides live in bounded, schema-checked repository content.
Each distinguishes two useful task choices, required inputs, review criteria and
stop conditions. They connect to current resource documents by actual category;
public builds never read private draft packages. Local previews label the linked
drafts explicitly. Category guidance has its own `editorial` discovery state,
which makes no host-test, installation or community-activity claim.

Category URLs use `/categories/[slug]/`, avoiding collisions with agent slugs at
`/agents/[slug]/`. Links are crawlable server-rendered anchors, with canonical
URLs and breadcrumbs. These pages remain noindex and outside the sitemap during
prelaunch review. Indexing requires a separate intent/value review and the broader
launch gate; the number of matching agents does not automatically enable indexing.
Category guides are not executable packages and confer no community reuse license.

Search supports agent, recipe and category types through the existing provider
interface. The visible type filter is reset with the query/category controls, and
individual publication states remain visible on narrow screens. No remote search
service, query logging or recurring cost is introduced.
